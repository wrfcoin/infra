# Legacy storage retirement

The paired backend change retires the storage-network and NAS simulations. This change removes their testnet full-profile service, compose overlays, internal edge route, bundle entry and smoke/readiness probes. It also removes direct deleted-source launch definitions in the NAS Docker image, NAS compose, K8s deployment/service/ingress and Unraid service; Unraid monitoring remains. Legacy control-panel NAS routes and the combined earnings view report unavailable, and the page disables NAS discovery.

The real IPFS-only storage-node and Kubo development stack remains in `infra/docker/docker-compose.storage.yml`. Testnet real storage and daily-summary archiving depend on the reviewed disabled profiles and real-client/worker changes (backend PRs 1421/1423, infra PRs 1174/1177). Retiring the mock does not enable either profile, publish a storage API, install an alert job or start a container.

Merge the real client, archive worker and disabled IPFS profiles before publishing this paired retirement. Merge the INFRA retirement first, then the backend retirement: this change stops bundling the backend mock, and deleting the backend file first would break the old image entry's build. After the backend retirement merges, refresh the header of the source-tree fixture (`scripts/tests/fixtures/esbuild-entries/backend-tree.txt`) to the actual backend commit in a follow-up. Rebuild backend images as part of an owner-run release; this patch changes no release pins, database schema, consensus feature or schedule. Retired mock APIs no longer serve fabricated provider capacity, NAS earnings or uploads. Existing consumers need the real daemon contract, rather than a port substitution.

The relaunch inventory in infra PR 1140 still configures the compute-agent with `STORAGE_API_URL=http://127.0.0.1:7000`. Its client posts multipart `/api/storage/upload`, while the real daemon accepts JSON/base64 `POST /api/store` and acknowledges an IPFS CID. That relaunch owner must retire the setting or provide an explicit consumer adapter before using this agent. The paired retirement does not change that owner's script or assert compute-agent storage compatibility.

Validation uses source-inventory controls, actual control-panel class/routes and generated browser functions with I/O doubles, compose rendering and repository suites. No live daemon, containers, hardware or host is queried.
